# Phase 5: Alarms, NAV/Waypoints, Demo and Safe Diagnostics

## Overview

**Priority P1, depends on Phases 1–4.** Finish all Chapter 1–3 operation flows dependent on alarm state, external sensor data, waypoint storage, System/Demo, and maintenance diagnostics. Covers inventory C01–C13 and remaining D items.

FURUNO Operator's Manual §§1.18–1.22, §§2.5–2.9 and Ch.3 are evidence sources. No actual NMEA, AIS transmitter, diagnostic test on real equipment or live ship data is authorized.

## Requirements

- [ ] Alarm profiles/enable conditions/thresholds, including fish/bottom/water temperature/speed/arrival/bottom type as supported; multiple alarm conditions behave correctly, audio acknowledgement and flashing indicators are separate from cause resolution.
- [ ] NAV1/NAV2 synthetic position/COG/SOG/heading/STW/wind/temperature/waypoint/distance and stale/no-data cases; correct units and timeouts.
- [ ] Waypoint MARK, list/rename/delete/destination/undo or cancel, and persistence; no invented GPS when source absent.
- [ ] System Demo On/Off: synthetic echo generation without transducer with authentic [DEMO] marker; distinct from instructor's separate scenario controls.
- [ ] Safe simulated battery alert, menu reset/clear/odometer, diagnostics/version and LCD test; any destructive operation is limited to simulated state with confirmation.
- [ ] Tankenmaru behavior only when profile says installed; never connect/transmit RF or serial.

## Implementation Steps

1. Assemble source-backed alarm transition tables: trigger, threshold, dependencies, sound/visual, acknowledge, clear, persistence and interacting menu. Map each to target unit screen/video.
2. **RED:** at least one success, false-positive, stale-source, acknowledge-with-cause-persistent, cause-clear, cancel and multiple-alarm ordering case per available alarm.
3. Add typed synthetic nav/temp/speed/wind observations to scenario core with explicit absent/stale values. Guarantee stale input cannot masquerade as measured depth or GPS.
4. Implement FCV-specific alarm reducer independent of decoration. Use separate training audio generated by browser only after user interaction and accessible visual equivalents.
5. Implement waypoint CRUD and destination workflow with testable storage scopes: factory defaults, saved device settings, lesson reset, power restart.
6. Implement System Demo and diagnostics as simulations with no hardware side effects; firmware display reflects target profile, never invent version.
7. Verify Chapter 3 status/maintenance screen availability but skip physical cleaning/fuse repair practice: they are reference guidance, not software controls.
